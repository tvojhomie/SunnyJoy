Проверка реального сервера в Unity Editor

ОБНОВЛЕНИЕ 2026-10-13: активен FirebaseRealtimeDatabase, а не config.php.
Ссылка читается GET-запросом из apps/sunny_joy/webview на каждом запуске.
Атрибуция и идентификаторы устройства в базу не отправляются. Кэш/постоянный
игровой режим ниже относятся только к старому HttpConfig. Подробности: FIREBASE_DB.txt.
Быстрая проверка без Play: Tools > Alien Project > Check Firebase DB Connection.

Быстрый запуск: открой MainMenu и нажми обычный Play в Unity.
Эта сцена автоматически запускает НОВУЮ изолированную QA-установку, реальный
запрос к серверу и окно Real Server Test. Нативный AppsFlyer в Editor не запускается.
Для проверки повторного запуска с кэшем используй кнопку в окне ниже.
Preview UI/Game и автоматические UI-тесты по-прежнему обходят сервер.

1. Открой Assets/Scenes/MainMenu.unity.
2. Tools > Alien Project > Test Real Server in Editor.
3. Нажми «Новая установка → реальный сервер».
   Unity сама войдёт в Play Mode. Не используй Preview UI/Game: они специально
   обходят серверный запуск для локальной проверки игры.
4. В окне Real Server Test видны JSON, ожидание HTTP, код и время ответа,
   разбор JSON и принятое сервером решение. HTTP-запрос идёт на Config URL
   из WebWrapperSettings; результат и web-адрес не подменяются.
   В Game View во время ожидания показывается авторский LoadingPanel с фоном,
   логотипом Egg Catcher и анимированной полосой. Полоса показывает активность,
   а не процент HTTP-запроса. При ошибке/офлайн открывается игра без экрана Retry;
   временный сбой не закрепляет игровой режим навсегда. Следующий запуск повторит проверку.
5. Если сервер выбрал WebView, страница открывается сразу: PushPanel и запрос
   разрешения не появляются. Если выбрана игра, сначала открывается главное меню
   (новому игроку сначала нужно создать профиль), затем появляется PushPanel:
   - Skip: остаться в меню без разрешения, отложить панель на 3 дня в тестовом состоянии.
   - Yes: окно Real Server Test предлагает Allow / Don't Allow (симуляция iOS).
     Оба варианта закрывают панель и оставляют игрока в меню. Реальное разрешение macOS/iOS
     не запрашивается и пуш-токен не создаётся.
6. Страница открывается настоящим UniWebView в отдельном небольшом окне macOS.
   Это нормальное поведение Editor-плагина; на iPhone WebView находится поверх приложения.
7. «Остановить тест» выходит из Play Mode. «Повторный запуск» сохраняет выбор
   сервера, срок жизни URL и результат тестового разрешения. Если кэш ещё действителен
   или уже выбран игровой режим, повторного HTTP-запроса по штатной логике не будет.
   Чтобы снова пройти запрос с начала, нажми «Новая установка».
   Выбранный вручную режим/повторный запуск не перезаписывается обычным Play-хуком.

Что настоящее
- UnityWebRequest POST к текущему Config URL, ожидание/ошибки/таймаут запроса;
- production LaunchCoordinator, JSON, решение сервера, кэш и сроки;
- блокировка игрового меню/музыки до игрового решения;
- собственная PushPanel, обработка Skip и результата разрешения;
- загрузка настоящего web-адреса, возвращённого сервером.

Что смоделировано
- Режим NonOrganicQa: af_id = unity-editor-<случайный GUID>, af_status = Non-organic,
  media_source = unity_editor, campaign = unity_editor_test, is_unity_editor = true.
- OrganicQa меняет af_status на Organic. NoNativeData отправляет пустой af_id,
  без af_status/campaign/media_source, с отметкой is_unity_editor.
- Это не настоящий SDK callback/установка AppsFlyer. Сервер может по-разному
  обработать эти режимы — тест не заставляет его открыть WebView или игру.
- Запрос использует iOS bundle/store ID, даже если Unity сейчас на Android Build Target.
- Настоящие OneLink Universal Links, APNs/FCM, push delivery, iOS permission dialogs,
  ATT/IDFA, подпись и нативную камеру iPhone можно проверить только на устройстве.

Безопасность теста
- Production WebWrapperSettings, Firebase-файлы и ключи не изменяются.
- Editor-состояние установки и игровой профиль отделены от обычных сохранений.
- Каждая новая тестовая установка получает новый явно тестовый ID.
- Ответ сервера может содержать персонализированный URL: query/fragment не пишутся
  в журнал этапов; настоящий URL передаётся только в WebView для загрузки.
- После выхода из Play Mode режим отключается; журнал остаётся до следующего теста.

Ветка игры: Loading → создание профиля (если нужно) → главное меню → PushPanel.
Ветка WebView: Loading → страница; PushPanel в этой ветке отсутствует.
Editor-проверка не заменяет end-to-end тест мобильных SDK на устройстве.
