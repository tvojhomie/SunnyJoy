Launch
Auto Start is on; real services are selected. Menu, profile and game audio wait
for the server's game decision. WebView launches do not start a hidden game.
Offline/startup errors and WebView loading failures open the game for the current session,
without an error/retry screen and without permanently overwriting saved server routing.
WebView opens directly, with no PushPanel and no notification permission request.
PushPanel is eligible only after the game menu is visible (after profile creation
for a new player), when permission is requestable and its cooldown has expired.
Yes requests native permission. Skip closes the panel without requesting it,
postponing it for at least 3 days. Native refusal suppresses repeated prompts.
Both choices return to the already-open game without reloading it.
The game stays portrait; WebView can rotate.

Screen adaptation
The foreground UI fits a 960x1920 design space uniformly inside Screen.safeArea;
the existing full-screen backgrounds remain edge-to-edge. Nested dialogs inherit
their parent's fit instead of applying the notch/home-indicator insets again.
Keyboard avoidance and photo dragging include the foreground's fitted scale.
Gameplay refreshes its camera bounds and player position after viewport changes.
Tools > Egg Catcher > Run Screen Adaptation Tests checks the authored buttons
and headers at 320x568, 375x812, 390x844, 430x932, 768x1024 and 844x390 with
simulated safe areas. Landscape here is a layout stress test; gameplay remains
portrait. Capture Screen Adaptation Preview renders disposable menu copies to
Library/ScreenAdaptation without changing the scene or profile. These are
authored layout renders, not screenshots from an iPhone or native SDK tests.
